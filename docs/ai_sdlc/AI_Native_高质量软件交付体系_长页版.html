AI-NATIVE SOFTWARE DELIVERY · IMPLEMENTATION MECHANISMSQUALITY OPERATING MODEL

四阶段落地机制：关键活动与质量门禁

每阶段聚焦 5 项关键措施，形成从规格准入到发布准入的可执行质量闭环

01　PLAN + DESIGN

需求与设计

明确业务需求与技术方案，确保可实现、可验证

1

意图澄清

明确业务目标、范围及约束，形成 intent.md

2

规格定义

细化业务规则、状态、场景与验收标准 AC

3

需求挑战

识别遗漏、歧义、冲突及不可验证项

4

方案评审

评估架构、依赖影响和关键技术风险

5

验证前置

依据 AC 与不变量建立测试义务

规格准入 · Spec ReadyGATE 1
02　BUILD + TEST LOOP

开发与测试

正确实现需求，持续发现并修复开发缺陷

1

先规划后编码

plan.md 定义变更范围、步骤与验证方法

2

规范化实现

用 CLAUDE.md / Skills 约束工程实现

3

测试先行

基于测试义务构建单元、集成和失败用例

4

自动反馈循环

构建、静态检查和测试自动执行与重跑

5

影响与代码审查

变更回归分析、Agent Review 与 CI 门禁

编码准出 · Code ReadyGATE 2
03　INDEPENDENT VERIFICATION

独立验证

独立确认业务正确性、场景覆盖和变更风险

1

独立验证

按批准需求与测试义务判定，不从代码反推

2

关键场景覆盖

覆盖正常、异常、边界、并发及状态转换

3

风险驱动回归

结合变更影响与历史缺陷，识别测试缺口

4

分层与真机验证

组合单元、集成、端到端与真机测试

5

证据与验收门禁

汇总测试证据、需求覆盖与剩余风险

验收准出 · Validation ReadyGATE 3
04　DEPLOY + MAINTAIN

发布与运行

安全发布、持续监控，并将线上问题闭环

1

发布门禁

基于质量证据、安全结果与审批执行部署

2

权限与操作控制

最小权限、环境隔离、Hooks 阻断风险操作

3

灰度与回滚

观察崩溃、ANR、业务指标并按阈值止损

4

监控与智能诊断

规则发现异常，Agent 分析日志与变更

5

知识与能力闭环

沉淀事故、测试和风险模式，以 Evals 评估

发布准入 · Release ReadyGATE 4
运行逻辑：规格与验证依据先行 → 开发边构建边验证 → 独立验收确认 → 风险可控后发布；不合格回到责任环节。责任明确 · 门禁可执行 · 证据可追溯
